# Pilot operations checklist / 試験営業チェックリスト / 試營運檢查清單

Pre-pilot readiness for the people running the restaurant. It records what the
code already exposes and marks everything else **not implemented**. It does not
deploy, approve a pilot or set thresholds: every owner and threshold cell is
`TBD (Owner)` until the Owner records a decision and receipt.
試験営業前の運用準備。コードに実装済みの範囲のみ記載し、未実装は明記する。
本清單供試營運現場使用；只列程式已實作的部分，其餘標示未實作；負責人與門檻一律 `TBD (Owner)`。

### 1. Monitoring and alerts

| Item | What the code has | Gap |
| --- | --- | --- |
| HTTP liveness | `GET /healthz` returning `{"status":"ok"}` in `cmd/server` (health-only), the guest/staff HTTP handlers in `internal/httpapi` (including `cmd/operationstest`) and the payments runtime. It does not check DB readiness. | `cmd/guesttest` has no `/healthz`. The deployed composition and a readiness check are `TBD (Owner)`. |
| Error rate, latency, 5xx | Nothing. No metrics, tracing or APM exporter exists in the repo. | Not implemented. Alert thresholds: `TBD (Owner)`. |
| Stripe webhook backlog | `stripe_webhook_events` stores each verified/rejected event with `received_at` and `processed_at`. | No endpoint, exporter or worker binary in `cmd/`. Query manually (below) until monitoring exists. |
| Payment work queue age | `stripe_payment_work` rows are `READY`, `LEASED` or `DONE`, with `available_at`, `lease_until` and `attempts`. | Same: manual SQL only; the production worker composition is not built (EXT-1). |
| DB disk, connections | Nothing in the app. | Not implemented; hosting-provider metric (`TBD (Owner)`). |
| Ingress abuse | No in-app throttling (D8). | 8h GAP until a deployed ingress is burst-tested with `cmd/bursttest`. |
| Logs | 8j evidence is local and finite. | Deployed proxy/APM/collector logging is separate; `TBD (Owner)`. |

Manual backlog queries (read-only, no secrets):

```sql
SELECT count(*) AS unprocessed FROM stripe_webhook_events WHERE processed_at IS NULL;
SELECT status, count(*), min(available_at) AS oldest_ready
FROM stripe_payment_work GROUP BY status;
```

### 2. Secrets

Names only; never put values in this repo, the DB or a ticket. Only the test and
demo runtimes read environment variables today; the production composition and
its secret manager are not built (EXT-3).

| Name | Read by | Where it must live |
| --- | --- | --- |
| `TOJIMA_DEMO_GATE_SECRET` | `cmd/demogateway` (at least 32 bytes, no line breaks) | Demo host environment outside the repo. |
| `TOJIMA_DEMO_PUBLIC_ORIGIN` | `cmd/demogateway` (not secret) | Demo host environment. |
| `TEST_DATABASE_URL` | `cmd/guesttest`, `cmd/operationstest` | Disposable loopback test databases only; never production. |
| `TOJIMA_STRIPE_MODE`, `TOJIMA_STRIPE_API_VERSION`, `TOJIMA_STRIPE_TEST_MAX_AMOUNT_JPY` | `cmd/operationstest -stripe-sandbox` (settings, not secrets) | Test shell only; see [Stripe Sandbox test runtime](../p80-stripe-test-runtime.md). |
| `TOJIMA_STRIPE_TEST_SECRET_KEY`, `TOJIMA_STRIPE_TEST_WEBHOOK_SECRET`, `TOJIMA_STRIPE_TEST_ACCOUNT_A/B/C` | `cmd/operationstest -stripe-sandbox` only | Test shell or test secret store; never committed or logged. |
| Demo/sandbox staff credentials and fixture webhook secret | Generated by `cmd/operationstest -payments-fixture` | Owner-only 0600 file outside the served web root. |

Production DB, IdP and payment secrets do not exist yet. Rotation step for the
demo gateway: stop it, replace `TOJIMA_DEMO_GATE_SECRET` with a new value of the
same rules, restart. Rotation owners and schedules for everything else are
`TBD (Owner)`.

### 3. Emergency stop

| Action | Exact path | Required role |
| --- | --- | --- |
| HQ hold one product across the tenant | `PUT /v1/admin/tenants/{tenantID}/menu/products/{productKey}/emergency-hold` with `active`, `reason`, `expected_version`, `idempotency_key` | `TENANT_ADMIN` with MFA |
| Pause a product for one store | `PUT /v1/admin/tenants/{tenantID}/stores/{storeID}/menu/availability` with status `PAUSED` | `STAFF_CASHIER` or `STORE_MANAGER`; MFA required for `STORE_MANAGER` |
| Close a table | `POST /v1/staff/tenants/{tenantID}/stores/{storeID}/tables/{tableID}/sessions/{sessionID}/close` | `STAFF_CASHIER` or `STORE_MANAGER`; MFA required for `STORE_MANAGER` |
| Request a stop for an order | `POST /v1/staff/.../sessions/{sessionID}/orders/{orderID}/stop-requests` | `STORE_MANAGER` with MFA |
| Confirm or reject a stop | `POST .../stop-requests/{requestID}/confirm` or `/reject` | `KITCHEN` |
| Withdraw or finalize a stop | `POST .../stop-requests/{requestID}/withdraw` or `/finalize` | `STORE_MANAGER` with MFA |
| Void an unpaid Stripe order (D9) | `POST .../orders/{orderID}/payment/void-unpaid` | `STORE_MANAGER` with MFA; the server re-checks the provider first |
| Block abusive traffic | Ingress rule, not the app (D8) | `TBD (Owner)` |

Releasing a pause (`AVAILABLE`) requires `STORE_MANAGER` with MFA. Closing a
table does not revoke independent ORDER_READ links (D6).

### 4. Staff procedures on failure

- **Payment provider down.** Stop taking card orders: pause the affected store's
  products or take orders as cash where the store allows it. Never mark a payment
  paid by hand; a manager void is allowed only after the server re-checks the
  provider (D9). Provider-side reconciliation remains EXT-1: `TBD (Owner)`.
- **KDS down.** Order state lives in the database (`operation_order_state`,
  `operation_kds_cards`). Continue accepting and advancing orders through the
  staff operations screens; READY is not SERVED, and a table closes only through
  the explicit close path above. Recovery criteria: `TBD (Owner)`.
- **Database restore.** Follow [Migration plan](../deploy-runbook.md) and
  [Backup/restore rehearsal](../deploy-runbook.md). Local restore evidence does
  not prove hosting backup, retention or RPO/RTO; 8n and EXT-3 stay GAP.

## 日本語

監視：実装済みは `GET /healthz`（`cmd/server`、`internal/httpapi` の guest/staff handler、
payments runtime。DB readiness は見ない。`cmd/guesttest` には無い）。
metrics／APM／アラート、`stripe_webhook_events` と `stripe_payment_work` の滞留可視化、
DB 容量・接続数は未実装で、担当・閾値は `TBD (Owner)`。手動確認は上記 SQL のみ。
8h の入口制限はアプリではなく ingress 側で、配備後の burst 試験まで GAP。

Secret は名前のみ：DEMO は `TOJIMA_DEMO_GATE_SECRET`／`TOJIMA_DEMO_PUBLIC_ORIGIN`、
試験は `TEST_DATABASE_URL`、Sandbox は `TOJIMA_STRIPE_*`（`-stripe-sandbox` のみ）。
本番の DB／IdP／決済 secret と Secret Manager、更新担当・周期は未実装／`TBD (Owner)`。
デモ gateway の更新は停止→新しい32バイト以上の値で再起動。値を文書・DB・ログに残さない。

緊急停止：本部停止は `TENANT_ADMIN`＋MFA、店舗の販売停止は `STAFF_CASHIER`／
`STORE_MANAGER`（`STORE_MANAGER` は MFA）、閉卓は `STAFF_CASHIER`／`STORE_MANAGER`（MFA）、
停止申請は `STORE_MANAGER`（MFA）、厨房の confirm／reject は `KITCHEN`、
未払い Stripe の取消は `STORE_MANAGER`＋MFA。通信の遮断は ingress（D8）。
障害時：決済停止では手動で支払済にせず、KDS 停止でも READY≠SERVED を守り明示閉卓のみ。
